## 仮説

実験中のenvelope版CNNは5層の出力24×16×8をflattenし、補助97値と合わせたhead7×3,169で判定する。head重みだけで22,183個ある。時間位置ごとに別の重みを持つ構成が、短い語や入力区間の変化への弱さに関係するかを調べる。今回の診断でこの原因を証明したわけではない。

次期案は時間の16cellを4領域へ平均poolingし、粗い順序と8つのband位置を残す。24×4×8＋energy64＋duration1＋band平均32でhead7×865になる。非負Q5値4個の和を4でfloor除算する整数処理を想定する。入力は2,145値のまま、特定の語への分岐は追加しない。

数値モデル＋5閾値は23,635−16,128＝**7,507Bの設計見積もり**。学習parameterも23,134−16,128＝7,006を想定する。C/RAM/速度/認識精度の実測ではない。時間の細部を失い、むしろ誤分類が増えるリスクがある。

## 次の契約

1. 新方式を明示した場合だけ新headを受け付け、既存の両形式を変えない。
2. 時間/周波数の軸、4cellの和・floor、head入力の順序を独立scalarと照合する。
3. Torch/export/整数演算の対応、入力不変、容量、CPU小型fit、step/期限を先行TDDで確認する。
4. 実装/source/容量確認後だけ、同じ元データ/保留条件/全24domainと結合条件で1構成のrecipeを固定する。追加224係数の凍結方式とは分け、全体の再学習を想定する。

既存の失敗を消さず、評価行の削除/再ラベル、消費済み最終2組の再利用、同じ閾値だけの探索をしない。実機a553/16app・実声6/15、Vast.ai累計0米ドルを維持する。
