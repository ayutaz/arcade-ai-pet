# 同一発話の切り出し範囲を対で比較する診断

2026-11-19。既存CNNの21/24条件の不採用を維持したまま、入力処理の影響を調べるホスト診断。モデル/閾値/データのラベルを変えない。[先行条件](../experiments/neural-domain-20261119/paired-windows-plan.json)。実データ1,803組の診断も完了した。品質改善候補の採用は行っていない。

## 比較するもの

同じ元発話とvariantに対し、cleanとhum/noise/earlyの処理済みPCMを対にする。発話検出（VAD）の区間、前後10frameの文脈、端で切れたframe数、log-mel/energy/発話長の差を記録する。earlyの既知の−2,400sampleは−15frameとして座標を揃える。

さらに、変化後のPCMを維持したまま、cleanのVAD区間を移動/切詰めした範囲だけを使って特徴を作る。これで「切り出し範囲だけを揃えた場合」に既存モデルの順位がどう変わるかを診断する。clean区間は正解の区間ではなく、この比較を本体へ配備できる処理とは扱わない。実際に音が切れた場合、その情報は取り戻せない。

`trace`は波形を返さず、frameとsampleの排他的終端を明記する。peak32未満は既存特徴処理のskipを明示し、架空の基準区間を割り当てない。`for_span`は指定範囲の特徴、`pair`は対の集計を返す。入出力の由来は呼出し側で検証する。

## 先行TDD

6契約を先に追加し、未実装moduleのImportErrorをRedとして確認した。実装後の最初のGreen試行は5/6件が成功し、残りはテストがscope文字列内の「pcm」を波形データと誤認した失敗。データのkey/型/長さを検査する形へテストを訂正し、6件/0.159秒が成功した。失敗ログは保持する。

```sh
uv run --locked python -m unittest discover -s tests -p test_paired_windows.py -v
```

独立scalarでのエネルギー閾値/区間、独立した面積重みpool、旧特徴との完全一致、±15frameの移動と端の切詰め、−32768/低peak、JSON化/入力不変/無効入力の早期拒否を確認した。

回帰327件/35.280秒、学習30件/3.624秒、固定SDK2件/2.781秒がskipなし成功。旧v3凍結13sourceもbyte不変。テストの成功を認識精度や実機の保証へ広げない。

## 固定した診断範囲

既存の開発用601例に対する1,803組、cleanを含む2,404特徴を保存済みcacheと照合する。4合成条件/20無音の保留、元archive/全評価条件は維持する。モデル8595204e…と5閾値を固定し、条件別の順位回復/悪化を数える。学習、ASR、消費済み独立最終データ、開発testの追加判定を使わない。

実機a553/16app・実声6/15、C/target未確認、Vast.ai累計0米ドルを維持する。

## 固定診断の結果

[結果と別照合](../experiments/neural-domain-20261119/paired-windows-result.json)。source906fc0fをarchiveし、13.545秒で完走。legacy270・保留neural266・元neural65の計601例/1,803組を比較した。実際の2,404特徴は旧cacheと完全一致し、cleanを含む12条件の混同行列も元の不採用結果と一致した。

| 元の品質未達条件 | 元の誤順位 | 区間を揃えて正解へ回復 | 逆に正解から悪化 | 同じ負例集合の誤反応（元→比較用） |
|---|---:|---:|---:|---|
| 保留neural / hum | 10 | 5 | 2 | 5/202 → 9/202 |
| 保留neural / noise | 8 | 1 | 0 | 8/202 → 6/202 |
| 元neural / early | 2 | 1 | 0 | 1/44 → 1/44 |

元の誤順位20件中16件で区間も変わっていたが、区間を揃えて回復したのは7件。新たに2件が悪化した。負例はcleanの参照区間が使える同じ集合で比較し、低peakで区間を持たない例を一方だけに含めない。63クラス行の全件数と特徴差の平均を記録から再計算し、33source/8元入力/モデル/3cacheのhashも再確認した。これは実装後の追加照合で、先行TDDとは別の証拠。

切り出しが影響する例は確認したが、VADだけの変更で品質を解決できる結果ではない。clean側でも既に誤順位の例が残り、humでは負例の誤反応が増える。参照区間を使う比較用の処理を実機用の改善候補として採用しない。既存21/24条件の不採用は維持する。
