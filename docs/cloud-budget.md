# プロジェクト累計の費用予約

**予算計算とSQLite台帳だけの実装。クラウドの起動・監視・成果物回収・解約を自動実行するツールではない。** このmoduleはAPIキーを読まず、ネットワークへ接続せず、課金操作を持たない。

## 予算と入力

AI Petの全Phase・再試行・OS統合を同じ`arcade-ai-pet`として累計100米ドルで管理する。通常予約は90ドル以内、残り10ドルは回収/請求反映遅れ等の余裕として保持する。既定台帳は`~/.local/state/scratch-arcade-lab/vast/arcade-ai-pet.sqlite3`で、repoや作業フォルダーごとに作り直さない。別path指定はテスト/移行用であり、実運用の上限をリセットする手段にしない。

| 費用 | 見積りに含める内容 |
|---|---|
| 実行 | GPUと割当storageを含む実行中の総時間単価 |
| 回収 | 同じ実行中単価×回収用の予約時間 |
| 停止後 | 確認済みの停止中単価×保持時間 |
| 通信 | download/uploadの単価×それぞれの最大量 |

`estimate`は新しい料金（60秒以内）、必要な全単価、最大/最小実行秒数、回収/保持時間を要求する。金額は有理数で計算し、予約額を1マイクロドル単位で切上げ、予算内の実行秒数を切下げる。未知・負・非有限の料金や期限切れを拒否する。

単価の単位と割当容量は実行側が正しく照合する必要がある。[Vast.aiの検索仕様](https://docs.vast.ai/api-reference/search/search-offers)ではstorageはGB/月、転送はGB単位の価格が別項目になる。[停止中もstorage課金が続く](https://docs.vast.ai/guides/instances/storage/types)ため、GPU停止を解約完了とは扱わない。

## 台帳の動作

1. `reserve`で使用済み/予約中の合計を検査し、同じrun IDを再使用しない。
2. API作成要求の前に`mark_creating`を1回だけ実行する。応答不明なら`mark_unknown`で予約を保持し、別IDによる再作成を止める。
3. `bind_instance`は外部で所有確認したIDだけを記録する。操作前に`owns_instance`を照合する。
4. 回収失敗は`recovery_failed`へ移し、新規予約を止める。
5. 成果物照合・instance解約・最終請求の全確認後だけ`settle`する。実費が予約を超えた場合も隠さず記録し、上限超過時は後続を拒否する。

未試行の予約だけは`cancel_unused`で解放できる。作成を試みた後の不明な費用は解放しない。再起動で台帳を初期化せず、SQLiteのtransactionで同時予約を直列化する。台帳は所有する通常ファイル/mode0600だけを受け付け、既存の不整合を削除して直さない。

`billing_complete`/`ownership_verified`等は実行側が外部の結果で確認する入力。フラグだけで実サービスへの確認が行われるわけではない。providerの監視・期限・料金の再照合・回収量上限・解約照合を実装/検証するまでは、有料ジョブを起動しない。通信障害を含む絶対的な請求上限を保証した実装ではない。
