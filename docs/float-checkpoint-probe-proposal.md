# float checkpointと整数版の対比較の次期案

2026-11-19。**未実装/未学習/recipe未固定。** [設計範囲](../experiments/neural-domain-20261119/float-checkpoint-probe-proposal.json)。[時間方向pooling版](time-pooled-head.md)も15/24条件で不採用だった。次の構成を試す前に、学習時のfloatモデルと整数版の差を直接観測する。

## 観測不足

これまでのCNN比較は整数版でcheckpoint/閾値を選び、floatの重みと判定を保存していない。既存のshadowは量子化済み係数を実数として計算したもので、元のfloat checkpointの復元ではない。したがって、モデルがfloatの段階で誤るのか、整数化で正しい順位を失うのかをまだ区別できない。

## 次の契約

1. 同じcheckpoint・同じ開発配列で、実際のTorch evalによるfloatの生logitと整数版を対にする。まず既存の選定用16条件で、クラス別の一致/順位回復/順位悪化を残す。float側の閾値探索は行わない。
2. 診断は明示選択とし、checkpointの選定と採用条件は整数版のまま。診断の有無で選定入力や評価行が変わらないことを先行TDDで確認する。元neuralの整数回帰を含む全24条件も維持する。
3. 選ばれたfloat stateを非公開の実験領域へ、source/データ/整数重みとの対応hash付きで残す。公開するのは集計/来歴だけとし、保存したstateから判定を再現できることを検証する。
4. 小型fixture、診断/非診断の対応、shape/値域/上限/不変を確認してから、既存のlog-mel構成1つの再計測recipeを固定する。今回の未保存float値を復元したとは扱わず、新しい学習結果と区別する。

floatでも誤るならデータ/特徴/分類器側、floatでは正しいのに整数で誤るなら量子化側への対策を検討する。混在する場合は件数を分ける。floatが必ず正しい/高精度とは仮定せず、新headや閾値だけの探索を先行させない。
