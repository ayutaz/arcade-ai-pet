# 入力条件の切分け

2026-11-18。c032/Petの実機音声操作が未達のため、モデルを固定してホストで入力条件を比較した。
**比較した4種類の前処理は全て不採用。実機の原因は未確定。** 本体録音・GPU・新FWは使っていない。

## 分かっている範囲

| 仮説 | 現在の証拠 | 次の検証 |
|---|---|---|
| 音が全く届かない | 既存録音診断で1,760Hz成分の増加あり | 発話の品質まで証明する結果ではない |
| 一定DCが原因 | c032は平均除去を実装したが、合成5語/近接5語とも0/5、実声1語も無反応 | 一定DCだけで原因を説明しない |
| 時間変動するDC/低周波 | 仮想入力で既存モデルの判定が崩れる | 下の比較ではhigh-passだけで全条件を満たさない |
| 音量・雑音・学習との違い | 合成条件を変えるだけでも判定が崩れる | 入力条件を加えた学習/独立評価を行う |
| 録音位置/分類エラー | driverは最初の1,600framesを捨て、その後32,000framesを取得。画面は5/6/-1を区別しない | 単純な画面無反応を特定のclassと断定しない |

平均除去は分類直前、録音の消費/消去は分類後。入力のPDM設定やGPIOは変更しない。
フレーム数の成立だけでは、発話が適切な音量・時刻に収まったと保証できない。

## 固定した比較条件

- モデルは配布済みKWS v2、重みSHA `91251ae7be454a62f9cd35607f3e2dbf6a4be8ce0b80342bd81f947e4a8e5527`、閾値0。
- 開発データのvalidation 270例だけを候補選択に使用。同一発話の加工版は元のsplitを維持。
- 元発話IDとWAV hashの開発/最終評価間の重複を拒否する。
- 4候補×8条件。全条件でF1>=0.90、対象外/無音の誤起動<=0.05、5操作のrecall>=0.80を要求。
- 全候補が不合格だったため、最終評価用の波形は開いていない。既存956例の実験結果と今回の結果を合算しない。
- 新しい条件は仮想的なストレスで、実測マイクの伝達特性ではない。2人の合成話者を未知の実人間と呼ばない。

| 条件 | 合成する変化 |
|---|---|
| clean | 変更なし |
| quiet | 振幅0.02倍 |
| dc | 振幅0.05倍＋DC 1,680 |
| drift | 振幅0.02倍＋DC 1,600＋480×exp(-t/0.3) |
| hum | 振幅0.05倍＋DC 1,600＋50Hz/振幅240 |
| noise | 振幅0.05倍＋DC 1,600＋標準偏差30の固定seed雑音 |
| early / late | 150ms前/後へ移動。窓外は切れる意図的なストレス |

前処理は平均除去、20/80/160Hzの一次high-pass＋平均除去。各録音で状態を初期化し、PCM16へ丸め/飽和する。
`native/conditioning.c`はホスト上の比較候補で、OSや実機へ組み込んだものではない。
既存frontendはpeak<32を無音特徴へ変換する。この境界も小音量での候補不成立を調べる対象で、実機原因とは断定しない。

[数値結果](experiments/channel-robustness-v1-rejected.json)は判定行列を含む。前処理だけで採用基準を満たすという小さい探索の印象は、この比較では支持されなかった。

| 条件 | 平均除去 F1 | HP20 F1 | HP80 F1 | HP160 F1 |
|---|---:|---:|---:|---:|
| clean | 1.000 | 1.000 | 1.000 | 0.994 |
| quiet | 0.867 | 0.867 | 0.855 | 0.854 |
| drift | 0.117 | 0.519 | 0.819 | 0.853 |
| hum | 0.120 | 0.136 | 0.181 | 0.189 |
| noise | 0.193 | 0.195 | 0.188 | 0.195 |

例えばhum条件の誤起動は平均除去43.2%、HP160では59.0%。低周波変動への一部改善だけで採用すると、別条件の誤起動を見落とす。
次は学習側の入力条件と、弱い音声を無音へ潰す境界を分けて比較する。未達を解消するために実声の受入目標を下げない。

## 再現

[合成原本の生成手順](reproduce-model.md)と[ライセンス](data-license.md)に従い、開発/最終評価の原本をローカルへ用意する。

```sh
uv run --locked python -m unittest discover -s tests -p test_channel_robustness.py -v
uv run --locked python -m arcade_ai_pet.channel_robustness \
  --model models/kws-v2 --development datasets/jtalk-aligned-v3 \
  --heldout datasets/jtalk-heldout-v1 --output reports/fresh-channel-evaluation
```

出力先は毎回未存在の名前にする。原本WAV/PCM・絶対パス・実機情報は結果JSONへ含めない。
最終データのmanifestは重複検査に使うが、候補不採用時は波形/特徴の評価を行わない。

## TDDと検証の範囲

1. 比較の契約テストを先に作成。`channel-robustness-red.log`では新module未実装のImportErrorを確認し、実装後7件成功。
2. runnerの契約を追加。最初のmock参照不足は試験準備の不備でありRedに数えない。import整理後、`evaluate_channels`未実装で失敗することを確認し、実装後8件成功。
3. WAV同一性の拒否テストを先に追加。重複を拒否せずmodelへ進む失敗を確認し、検査追加後10件成功。
4. 2回のvalidation比較を実行。初回と同じ全候補不採用を確認し、WAV重複検査を含む2回目を数値記録に保存した。最終評価はどちらも未実施。

Red/Greenの実行は上のunittestコマンド。raw logはGit対象外のreportsに保存。
検査したのはホストの信号処理/集計/選択と既存コードの回帰。実機での精度、録音品質、表示、聴取の証拠ではない。
標準67件、学習5件、既存SDKの両VM統合2件が成功。合成モデルや実機FWの更新は行っていない。
