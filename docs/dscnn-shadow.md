# 固定CNNの中間値丸めの比較

後続の[処理段階の内容点検](utterance-stages.md)は80呼出しを完走。ASRのgain感度もあり、誤ラベルと即断せず元の不採用を維持する。

2026-11-19。`dscnn_shadow.scores`は、保存済みのint8重み/int32 bias/shiftを変えず、float64で計算するホスト専用の診断。入力Q5化・中間値の切捨て・出力整数化を外し、ReLU6と層構成は維持する。Q10相当の単位を持つfloat64の7出力を返す。

**元のfloat学習checkpointの復元ではない。** 重み/biasの量子化前の値は戻せず、その量子化による精度低下は判定できない。shadowを採用モデルやESP32-S3の実装とは扱わない。

## TDD

4契約を先に追加し、未実装moduleのimport失敗をRedとして確認。その後に最小実装した。

```sh
uv run --locked python -m unittest discover -s tests -p test_dscnn_shadow.py -v
```

4件/0.141秒が成功。全5畳み込みとheadを別のPython scalarループ/`math.fsum`に照合し、biasのQ5基準、出力channel別shift、ReLU6、NCHWのflatten、tailの半Q5値、int32での未飽和、batch分割、入力/重み不変を検査する。回帰286件/33.108秒、学習21件/3.176秒、SDK2件/2.489秒もskipなし成功。

## 比較の固定条件

[比較前の条件](../experiments/neural-domain-20261119/logmel-shadow-plan.json)で、同じ重み/5閾値と開発用24条件/4,808行を使う。旧整数版の全混同行列を再現してからshadowと比較する。shadowの閾値判定用変換はties-to-evenでQ10整数へ丸め、int32へ飽和する。float出力からの順位変化も別に数え、入力/中間値の丸めと混同しない。

学習・閾値変更・新しい最終データ・C移植・実機操作は行わない。分類の誤りが同じままなら丸めだけで直るとは判断しない。差があっても、新しい整数候補/独立評価/S3資源の検証は別工程にする。[前の誤り診断](development-errors.md)を保持する。

## 固定モデルの比較結果

[数値と照合](../experiments/neural-domain-20261119/logmel-shadow-result.json)。source `06b9ac5bd5af3ec93ee94c2ab0b53c8fe7fd0390`をarchiveし、同じ重み/5閾値/開発用4,808行で比較した。元の24混同行列は再現。shadowの24指標も別計算し、31source/8元入力・モデルを保持した。

| 計算 | 合格domain/profile | 最小F1 | 最大誤反応 | 最小操作recall |
|---|---:|---:|---:|---:|
| 元のQ5整数版 | 21/24 | 0.884537 | 0.038835 | 0.833333 |
| 丸めなしshadow | 19/24 | 0.888662 | 0.033981 | 0.833333 |

shadowは保留hum/noise/early/lateと元検証earlyでF1未達。全4,808行で1位は24行、最終判定は19行変わったが、操作の1位正解へ改善した例と正解から悪化した例はどちらも0件。閾値比較のためのhead整数化で順位が変わった例やint32範囲外は0件だった。**中間値の丸めを外すだけでは、主要な操作の誤分類を救えなかった。** 重み量子化前との差を否定した結果ではない。

### 保存失敗と復旧

最初の実行は集計後のJSON保存でNumPy int64の`TypeError`となりexit1。失敗ログと空の出力はローカルで保持した。実driverの集計式を読む回帰契約で同じRedを再現し、合格数をPython intへ変換後に1件/0.001秒が成功。

再学習や音声の再生成はせず、保存済みvalidation特徴を読み、モデル/source/入力hashと元24混同行列を再照合して集計を復旧した。復旧はexit0、1.669秒で、元実行の全処理時間とは区別する。公開ライブラリ4契約/回帰309件に、ローカルdriverの回帰1件を混ぜて数えない。
