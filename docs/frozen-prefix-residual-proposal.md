## 仮説と固定範囲

旧21/24候補`8595204e…`も不採用のまま、その数値係数を固定した土台として使う。新2,145入力の追加32値に対応する7×32=224係数だけを0から学習する。特定の語への手作業の分岐は設けない。

| 区分 | 方針 |
|---|---|
| 既存5畳み込み層 | 重み/bias/shiftをbyte不変にする |
| Headの既存3,137列 | 重みとbias/shiftをbyte不変にする |
| Headの追加32列 | 224係数だけを学習。既存row shiftを使うint8の範囲へ制約する |
| 特徴 | 既存prefix＋band平均32値。前後10frameは維持する |
| 選定 | 実際の整数演算で比較。float lossだけで採用しない |

追加係数0の状態で、旧候補と全整数logitが一致することを先に保証する。学習後の判定まで旧版と不変という意味ではない。数値モデル/5閾値23,635Bは同じ計算だが、C/総RAM/速度は未確認。

## 実装前の契約

1. 固定土台の型/shape/容量/入力を検査し、元の配列を変更せず新headを作る。
2. Head丸め前のaccumulatorを別scalar計算と照合し、0追加時の旧logit一致を確認する。
3. 固定係数のbyte不変、224係数だけの更新、整数化/飽和/期限/step上限を先行TDDで検証する。固定row shiftでは修正幅が不足するリスクも結果として残す。
4. 同じ元データと保留/全評価条件を維持して、実装/source/容量確認後に1構成だけのrecipeを固定する。閾値表の追加探索やASR不一致による行の削除/再ラベルをしない。
5. 全24domain・結合/選定条件と元neural回帰を通過した場合だけ、新形式のC照合/正式freeze/新しい独立最終評価/S3資源へ進む。
